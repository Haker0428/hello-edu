# 🎓 AI 自适应教学与学生知识画像平台

> 🎯 **核心定位**：不是记录学生"考了多少分"，而是持续回答——**为什么丢分、当前掌握了什么、下一步应该练什么**，并把结果转成教师可执行的教学动作。

## 一、需求背景

目标是为班主任和学科教师提供一套可定制的**学生成绩与学习状态管理系统**。系统围绕某一学期课程建立知识体系，通过作业、练习、考试持续估计学生对各知识点的掌握情况，并据此为不同学生生成针对性练习。

**核心闭环：**

```
课程 → 知识点 → 题目 → 学生作答 → 错因/得分点 → 掌握度 → 学生画像 → 个性化练习 → 再评估
```

## 二、产品核心原则

- 成绩不是终点，**知识掌握状态**才是核心状态。
- AI 不直接决定学生学什么，而是与**可解释的知识掌握模型**共同工作。
- **教师策略优先于个性化算法**，教师始终拥有教学范围、题量、难度和个性化比例控制权。
- 尽量不改变学校原有工作流，先兼容普通试卷、Excel 成绩和纸质作业，再逐步数字化。
- 老师不维护画像；老师正常教学，学生画像应由作答数据自动生长。
- Dashboard 不是单纯展示数据，而应成为 **Action Dashboard**：每一个异常后面都可以直接发起复习、专项练习或学生干预。

## 三、课程与知识体系

### 3.1 知识地图

课程拆解建议采用：

```
课程
└─ 章节
   └─ 知识点
      └─ 可测量能力点
```

例如"一元一次方程 → 移项 → 能否正确判断移项后的符号变化"。真正驱动个性化练习的应是最底层、**可测量的能力点**，而不仅是教材章节名。

### 3.2 平台标准 + 学校 + 教师三级体系

采用三层结构：

```
平台标准知识图谱
↓
学校课程体系
↓
教师教学配置
```

- 平台维护教材版本对应的标准知识 ID、前置关系、学习目标和常见错误类型。
- 学校教研组可以建立校级课程结构。
- 教师可以开启/关闭知识点、修改显示名称、增加自定义知识点。

教师允许修改"显示名"，但尽量保持底层语义 ID 稳定，避免同一知识被拆成多个不同 ID。

### 3.3 知识依赖关系

知识点之间需要 **prerequisite** 关系，例如：

```
有理数运算 → 整式运算 → 去括号 → 移项 → 一元一次方程 → 方程应用题
```

当高层知识点表现差时，系统不能只反复刷高层题，而应向下寻找真正的前置知识断点。

## 四、题目模型

### 4.1 一题可关联多个知识点

一道题不能简单只标"一元一次方程"，而可以拆成：

| 知识点 | 占比 |
| --- | --- |
| 去括号 | 30% |
| 移项 | 30% |
| 合并同类项 | 20% |
| 有理数运算 | 20% |

复杂解答题还应进一步拆成**步骤/得分点 Rubric**，使系统能够判断学生究竟在哪一步出现问题。

### 4.2 难度不是单一星级

题目建议维护 **Difficulty Profile**：

- 知识层级
- 计算复杂度
- 推理复杂度
- 文字理解复杂度
- 涉及知识点数量

这样才能针对"知识会但容易算错""建模弱但计算强"等不同学生生成真正有差异的练习。

### 4.3 题库优先，AI 变式辅助

第一阶段不采用"LLM 无限自由出题"，建议：

```
标准题库为主 + AI 变式生成 + 自动答案/步骤校验
```

以保证知识点、难度、答案和解题过程可控。

## 五、学生掌握度模型

每个学生、每个知识点维护：

- **Mastery**：系统认为学生目前会不会。
- **Confidence**：系统对这个判断有多确定。

即：

```
Student × KnowledgePoint → Mastery + Confidence
```

### 5.1 每次作答产生 Evidence

作答证据可以包含：

- 正确性
- 题目难度
- 是否独立完成
- 是否使用提示
- 作答时间
- 错误类型
- 题目质量/置信度

第一版可采用可解释规则模型，而不是直接上复杂深度模型。

### 5.2 初版更新方法

可先使用指数移动更新：

$$M_{t+1} = (1-\alpha)\,M_t + \alpha\,E_t$$

其中 $E_t$ 为当前题产生的证据评分，$\alpha$ 根据当前置信度、数据量、题目难度动态调整。

数据少时，新证据权重大；数据多时，一次偶然失误不应导致画像剧烈波动。

### 5.3 时间与遗忘

长期未验证时，更推荐先降低 **Confidence**，而不是直接把 Mastery 大幅降低。例如：

- 3 个月前：Mastery 92 / Confidence 96
- 当前：Mastery 92 / Confidence 55

系统因此安排"复习检测题"，重新确认是否仍然掌握。

### 5.4 教师可读状态

对教师展示时，可把内部百分比映射为：

```
未学习 → 未掌握 → 学习中 → 初步掌握 → 熟练 → 稳定掌握
```

降低教师理解成本。

后续算法可逐渐演进至 BKT / IRT / DKT，但前期优先可解释性和可验证性。

## 六、学生画像不只有知识点

最终画像建议分成三个维度：

| 维度 | 示例 |
| --- | --- |
| **Knowledge**｜知识 | 移项 60%、绝对值 90% |
| **Skill**｜能力 | 计算能力、建模能力、阅读信息提取、逻辑推理 |
| **Error Pattern**｜错误模式 | 符号错误、漏条件、计算粗心、步骤跳跃 |

**重要原则**：知识点和错误类型是两个独立体系。例如"移项"是 Knowledge，"移项后未变号"是 Error Pattern。

## 七、普通试卷如何进入系统

现实落地优先兼容学校现有考试流程：

```
试卷 PDF / Word / 拍照
↓
AI 自动拆题
↓
自动标知识点、难度、得分点
↓
教师快速确认
↓
导入学生逐题得分
↓
自动生成学生知识画像
```

**数据接入分三级：**

- **Level 1**：Excel 导入逐题得分 —— MVP 首选。
- **Level 2**：标准答题卡自动识别。
- **Level 3**：识别学生完整手写解题过程并做错因诊断。

第一版不应把大量研发成本投入手写 OCR，而应优先验证"诊断结果和个性化练习是否真正给老师带来价值"。

## 八、个性化练习引擎

个性化练习应拆成两层：

- **Practice Planner**：回答：这个学生下一步应该练什么？
- **Question Selector / Generator**：回答：具体用哪些题？

例如 10 道题可采用：

- 50% 薄弱知识
- 20% 前置知识
- 20% 当前教学内容
- 10% 历史复习

实际比例由教师策略模板控制。

### 公共作业 + 个性化作业

$$Homework = Common + Personalized$$

建议：例如统一题 60%，个性化题 40%。这样既保留班级教学节奏，又能照顾个体差异。

### 自适应难度

目标不是让学生全对，也不是持续受挫，而是动态维持适合当前水平的成功率。连续正确时提升难度；连续错误时降低难度，必要时切换到前置知识诊断。

## 九、教师端工作流

### 9.1 学科教师

重点管理"知识"。核心工作流：

```
备课 → 看前置知识状态 → 上课 → 随堂反馈 → 布置作业 → 查看异常 → 教学干预
```

教师首页优先回答：

1. 今天班级有什么问题？
2. 哪些学生需要关注？
3. 下一步应该做什么？

采用 **Exception-based Management**：系统自动把 40 名学生压缩成"正常 / 需关注 / 高风险"，教师主要处理异常学生和异常知识点。

### 9.2 班主任

班主任重点管理"人"，而不是单一学科知识。跨学科画像应提供：

- 各学科趋势
- 作业完成情况
- 跨学科共性问题
- 风险学生
- 已采取干预及效果

未来可发现如"数学应用题 + 物理文字题 + 化学实验题同时较弱"，进一步归因为"阅读信息提取 / 建模能力"问题。

## 十、教学干预闭环

系统不应只发现问题，还应记录：

```
问题 → 教师干预 → 后续表现 → 干预效果
```

例如某学生移项掌握度 42%，完成专项训练后一周升至 76%，系统记录本次干预有效。

长期可积累"什么类型学生对什么干预方式更有效"的数据，逐渐形成教学策略推荐能力。

## 十一、三层闭环

| 闭环 | 链路 |
| --- | --- |
| 题目闭环 | 题目 → 作答 → 错因 → 掌握度 |
| 教学闭环 | 知识状态 → 教学/练习 → 评估 → 调整 |
| 学生成长闭环 | 跨学科表现 → 发现问题 → 干预 → 追踪 → 验证效果 |

## 十二、核心数据模型

建议至少包含：

`School` `Class` `Teacher` `Student` `Curriculum` `Course` `Chapter` `KnowledgePoint` `LearningObjective` `Question` `QuestionKnowledgeMapping` `QuestionDifficulty` `ScoringRubric` `Exercise` `StudentAnswer` `ErrorType` `StudentMastery` `StudentSkill` `StudentErrorProfile` `Intervention`

核心事件是 **StudentAnswer**。每一次作答触发评分、错因分析、知识点归因、掌握度更新、置信度更新、画像更新和下一轮练习调整。

## 十三、MVP 范围

第一版严格收敛到六件事：

1. 创建班级并导入学生。
2. 选择教材，自动加载标准知识点体系。
3. 上传普通试卷，AI 自动拆题并标知识点。
4. Excel 导入每位学生的逐题得分。
5. 自动生成班级知识热力图 + 学生个人知识画像。
6. 根据画像生成下一轮个性化练习。

**MVP 核心验证闭环：**

```
考试 → 诊断 → 个性化练习 → 再考试
```

暂不优先做：手写 OCR、复杂 AI Tutor、家长端、全量课堂数字化。

## 十四、后续演进

- **V1**｜成绩 → 知识点掌握度
  回答：学生哪里不会？
- **V2**｜知识画像 → 个性化练习
  回答：下一步应该练什么？
- **V3**｜AI Tutor
  进一步实现：为什么错 → 缺哪个前置知识 → 怎么讲 → 出更简单题 → 再验证 → 逐渐提升难度

## 十五、当前待讨论问题

- 学生端应该如何设计，既体现个性化又避免"补差感"。
- 第一阶段选数学单科还是多学科验证。
- 如何定义首个真实教材版本与知识图谱粒度。
- Mastery V1 的具体参数、阈值及校准方式。
- 题库来源与 AI 变式题质量验证机制。
- 教师访谈中应优先验证哪些高频工作流和痛点。

## 十六、AI 多维评级

| 维度 | 评级 | 说明 |
| --- | :---: | --- |
| 用户价值 | ⭐⭐⭐⭐⭐ | 直接解决教师难以持续追踪每个学生知识掌握状态的问题 |
| 差异化 | ⭐⭐⭐⭐ | 单点能力并不新，但"知识图谱 + 可解释掌握度 + 教师工作流 + 个性化练习闭环"组合具有明显价值 |
| 实现可行性 | ⭐⭐⭐⭐ | Excel 逐题成绩 + PDF 拆题即可做 MVP，不必先攻克 OCR 和完整 AI Tutor |
| 商业潜力 | ⭐⭐⭐⭐ | 学校、教培机构和教师端都存在潜在付费场景，但真实采购链路仍需验证 |
| 增长潜力 | ⭐⭐⭐⭐ | 可从单科扩展到多学科、年级、学校和学生端 |
| 长期壁垒 | ⭐⭐⭐⭐ | 真正壁垒来自长期积累的题目-知识映射、学生学习轨迹、干预效果和学校工作流数据 |
| **综合 AI 评级** | ⭐⭐⭐⭐ | |

**AI 评语**：核心价值不是 AI 出题，而是把考试和日常练习转化为持续更新的知识画像，再直接驱动教师干预和下一轮练习。MVP 可以用现有试卷与 Excel 快速验证，实施路径较清晰。当前最大不确定性是学校真实工作流接受度、题目知识标注质量，以及个性化练习能否显著提高教学效率和学习效果。

## 十七、下一步

优先做**教师需求验证 + MVP 原型定义**：选择一个数学学期、1 套教材、1 个班级作为样例，完整走通"试卷拆题 → 知识点标注 → Excel 逐题得分 → 班级热力图 → 学生画像 → 个性化练习"的端到端流程，再决定学生端和更复杂算法是否进入下一阶段。
