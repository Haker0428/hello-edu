## 1. 项目速览（与本模块相关的部分）

**智卷工坊的受控生成链**：

```
Phase 1 需求分析 → 用户确认 → Phase 2 结构化生成
校验链：JSON 提取（容忍 Markdown 代码块包裹）→ Zod schema 校验 → 题型策略校验
       → 格式错误自动回喂自我修正
配置：OpenAI 兼容任意端点（含 Ollama 本地）；per-model temperature/max tokens；密钥入钥匙串
```

**MathBank 的 Harness 工程化**（README 明确称为 "AI Agent/Harness 工作流"）：

```
- 置信度路由：原生文本优先（省视觉 token），VLM 按页按需
- 闭环自愈：TikZ 生成 → XeLaTeX 编译 → 失败日志 + 视觉诊断 → AI 纠错循环（有界重试）
- 并发管道：文档解析 → 切片 → 打标 → 结构化 JSON 容错校验 → 异步并发 AI 解题
- 工程件：prompts.py 提示构建器集中管理 / ai_json.py 容错解析 / ai_providers.py 多模型
         task_manager.py 有界异步任务·取消·资源生命周期 / latex_diagnostics.py 错误定位
- 模型分工：文本推理 DeepSeek ｜ OCR 必须 VLM（Qwen-VL 等）｜ 绘图 GPT/Gemini
```

## 2. 值得吸收的点

### 2.1 Provider 按"能力位"配置，而非单一 Provider ★立刻采纳（修订 ADR-6）

MathBank 的实践证明**一个部署里需要多模型分工**（文本 vs 视觉）。我们原 ADR-6 的 `AI_PROVIDER` 单值设计不够用。修订：

```yaml
# 部署配置
ai:
  text:   { provider: openai_compat, model: deepseek-v3, temperature: 0.05 }   # 拆题/标注/变式
  vision: { provider: vllm,        model: qwen-vl,      }                      # P1.5 OCR（见 05）
  # P3 可加: reasoner（难题验算）/ embed（题目相似度）
```

Provider 抽象接口不变，配置从「指向一个」改为「按能力位一组」。这同时服务私有化形态（视觉模型可单独走校内 GPU）。

### 2.2 声明式 Schema + 分层校验 + 自我修正 ★采纳（智卷工坊）

我们的「结构化输出 + 重试 ≤2 次」升级为明确的四层链（代码结构照此组织）：

```
L1 提取：容忍 ```json 包裹 / 前后杂文的容错 JSON 提取（ai_json 的活）
L2 通用 schema 校验：pydantic（对应它的 Zod）
L3 领域策略校验：拆题的题号连续/分值总和；标注的候选集约束；变式的映射一致
L4 自我修正：校验失败把「错误清单」结构化回喂，重试 ≤2 次；仍失败 → 步骤 failed
```

关键细节：回喂的是**结构化错误清单**（哪条、错什么、期望什么），不是模糊的"格式不对"——修正成功率差异很大。

### 2.3 两阶段生成用于变式与 AI 出卷场景 ★采纳（P3 规格）

智卷工坊 Phase1（分析→确认）→ Phase2（生成）与我们"草稿→确认"同构，直接作为 **P3 变式生成**的交互规格：教师发起 → AI 先出「变式计划」（改什么数字/语境、考点不变声明）→ 教师确认 → 批量生成 → 校验器 → 入库草稿。

### 2.4 Harness 工程三件套 ★采纳（Celery 侧落地）

MathBank task_manager 的三原则直接写进我们的任务纪律：

1. **有界**：并发上限（per-school 队列限流，防一次大导入打爆 LLM 配额）；
2. **可取消**：长任务（整卷拆解、批量变式）支持取消，资源随任务回收；
3. **诊断结构化**：每步产物带 `{step, input_sha, output, error?}`（我们的 paper 状态机已有雏形，补 input_sha 便于评测集对齐）。

闭环自愈（有界重试循环）思想已含在 L4；TikZ 编译回路本身不吸收（05 已决策）。

### 2.5 提示词集中管理 ★印证

MathBank 把 OCR/解题/拆卷/组卷 prompt 全部收在 `prompts.py` 构建器。我们的 prompt 必须同样集中（一个包内文件），**禁止散落在业务代码里**——这是评测集回归（换模型跑指标）的前提。补一条纪律：prompt 改动走代码评审 + 触发评测回归。

### 2.6 联网搜索联动（智卷工坊）★P3 观察

模型在生成轮内按需提出搜索请求（Tavily/Exa/Firecrawl）。对 P3 的应用题情境生成（时事/生活语境）有价值，P1-P2 不做；记入演进预留。

## 3. 明确不吸收的点

| 项 | 理由 |
| --- | --- |
| MathBank 推荐第三方中转站的用法 | 合规风险（面向学校的 SaaS 不能走来路不明的中转）；我们只支持官方 API / 自部署端点 |
| 题库全量导出给 LLM 自由组卷 | 我们的组卷走结构化选题（practice），LLM 只做拆题/标注/变式的窄任务，上下文按需注入（且过滤答案，见 04 §2.3） |
| AGPL 代码（ai_providers/ai_json 等） | 思想吸收，代码自研（这几个组件本身也不复杂） |
