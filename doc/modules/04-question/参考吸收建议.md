## 2. 值得吸收的点

### 2.1 题干富内容格式定为 Markdown + KaTeX 子集 ★采纳

两个项目不约而同用「富标记 + 数学公式渲染」而非纯文本。我们的 `question.stem TEXT` 需要升级决策：

- **P1 起统一定为 Markdown + KaTeX**（`$...$` 行内、`$$...$$` 块级），前端 remark-math/rehype-katex 渲染（与智卷工坊同栈）。
- 吸收 MathBank 的**宏规范化思路**：定义受控标记（如填空 `____`、括号选择 `()`），入库前跑 normalize 脚本统一写法——避免同义标记越积越多，检索和变式替换都受益。
- LaTex 完整语法（MathBank 路线）不进 P1：渲染依赖重，KaTeX 子集覆盖 K12 数学足够。

### 2.2 智卷工坊的题目 JSON Schema —— 印证并补齐我们的字段 ★采纳

它的题目结构：`{题型, 题干, 选项, 分值, 参考答案, 评分点[], 解析}`。与我们 `question + scoring_rubric` 对照：

- **评分点是一等字段**而非事后补录——印证我们 Rubric 设计的方向，且提示：AI 拆题（05 模块）时可以让 LLM **顺带输出得分点草稿**（解答题），进确认队列。这比"教师后补"的摩擦低一个量级，把原设计 §4.6 的「Rubric 占位」升级为「Rubric AI 草稿 + 确认」。
- **题型枚举对齐**：单选/多选/判断/填空/解答（我们 `type` 枚举扩展 `multi_choice`，并给每型定义渲染模板与作答版式）。

### 2.3 MathBank 的 AI 只读题库（防答案泄露）★采纳

`questions_library.md` 把题库导出为 **LLM 上下文时过滤答案**，防止 AI 在组卷/解题输出中直接泄露答案。落点：

- 我们 ai 模块（12-ai）所有把题库注入 prompt 的场景（组卷上下文、变式母题、错题归类）统一走 `QuestionForLLM` 投影：**剔除 answer/analysis/rubric 答案分**。
- 补进 04 模块的接口约束：题库 → LLM 的序列化函数只有这一个出口。

### 2.4 MathBank 的 CLI 检索与"关联题目" ★参考

`scripts/search_questions.py`：`-q` 关键词、`-n` 数量、`-t` 题型、`-d` 难度、`-r` 关联题目。两点吸收：

- 运营/教研侧需要一个**管理检索台**（我们只设计了给 practice 的 `:select` 服务接口）；P2 的题库管理界面直接参考这套参数面。
- `-r` 关联题目 ≈ 我们的变式题母子关联（`parent_question_id`）。它验证了"同源题族"是题库的真实使用形态——我们在 :select 的 `prefer_retest` 之外，可加 `family_exclude`（同题族去重，避免一出就是换数字的姐妹题）。

## 3. 明确不吸收的点

| 项 | 理由 |
| --- | --- |
| SQLite 单机题库 | 我们多租户 PG + RLS，架构前提不同 |
| MathBank 无"一题多知识点带权重" | 它是大纲打标（一点归属），我们的 `question_kp_map.weight` 是掌握度引擎证据分摊的根基，**不可简化** |
| 题目无版本化 | 我们事件锚定题目版本（§4.3）服务于历史回放，两项目都没有这个诉求，保持不变 |
| MathBank 的 LaTeX 全文存储 | 见 §2.1，KaTeX 子集足够，避免渲染管线依赖 XeLaTeX |
