# 参考吸收建议 · 试卷接入（ingestion · paper）

> 分析对象：[JudgePeach/math-question-bank](https://github.com/JudgePeach/math-question-bank)（MathBank）· [DreZeo/examcraft-ai](https://github.com/DreZeo/examcraft-ai)（智卷工坊）
> 关联度：MathBank ★★★（**本项目最深的积累恰在我们的关键路径上**）· 智卷工坊 ★（不做导入，仅校验理念）
> 日期：2026-09-30 · 基于两仓库 README 与目录结构分析

## 1. 项目速览（与本模块相关的部分）

MathBank 的 PDF/Word 试卷拆解是双项目里工程深度最高的部分：

```
PDF：Inspector 属性探测 → 页级置信度路由
     ├─ 原生矢量文本直提（默认推荐：毫秒级、0 视觉 token）
     ├─ 低置信/公式丢失 → 自动降级 VLM OCR（Qwen-VL 等）
     └─ 手动"全图视觉 OCR"兜底通道
Word：OMML 公式解析 + MathType OLE 的 MTEF v5 记录树解析
      递归保留超链接/修订/Symbol 字符 → Markdown/内嵌 LaTeX
报告：拆卷报告按处理方式分类计数（结构转换 / 内嵌 LaTeX / 有限兼容 / 人工核对）
```

## 2. 值得吸收的点

### 2.1 PDF 解析从"P1 两级"升级为"三级分流" ★重点采纳

我们原设计 §4.2 只有「文字版 PDF 直提 / 扫描件 failed」两级。MathBank 证明中间态才是常态（文字层在但公式丢、部分页扫描）。修订为：

```
L1 原生矢量直提（默认，0 token）—— 文字层置信度探测通过即走
L2 混合页降级 —— Inspector 页级路由：低置信页单独走 VLM OCR，好页不花视觉 token
L3 全图 VLM OCR —— 扫描件/照片（兜底，手动确认开启）
```

关键吸收点不是"要上 OCR"，而是 **Inspector 的页级置信度路由思路**：把视觉 token 花在必要的页上。这直接改我们 P1 的成本模型和失败面（扫描件从"直接失败引导转 Word"变成"提示将启用视觉识别，耗时/成本较高，教师确认后执行"——仍保持教师知情与控制权，符合产品原则 P2）。

> 落地节奏调整：P1 仍只做 L1；**L2/L3 从 P2 提前到 P1.5**（作为答题卡采集前置能力），优先级依据见 06 模块（采集摩擦是生死线）。

### 2.2 Word 公式解析：MTEF/OMML + 低置信保原图 ★采纳进 P2 规格

MathBank 处理 Word 数学试卷的现实方案：

- OMML 与 MathType OLE（MTEF v5）双通道解析；
- **不能高置信转换的公式保留原预览图 + 标记人工核对**，拆卷报告分类计数。

第二点是"AI 只产草稿"原则在**文档解析层**的同构表达——解析器也有置信度，不确定就降级为图像证据。我们的 Word 导入（原设计未展开，只写了 PDF）按此规格补：

| 转换置信度 | 处理 | 拆卷报告归类 |
| --- | --- | --- |
| 高（纯文本/标准 OMML） | 直转 Markdown+KaTeX | 结构转换 |
| 中（内嵌 LaTeX 可靠） | 保留 LaTeX 原文 | 内嵌 LaTeX |
| 低（MTEF 疑难/乱码） | 截原公式图 + 标记核对 | 人工核对 |

### 2.3 跨页题缝合与清洗作为拆题前置步骤 ★采纳

题干跨页、页眉页脚、双栏排版是拆题错误的主要来源。把「跨页缝合 → 清洗 → 题号锚定」独立为流水线一步（产物可检查），比让 LLM 直接啃原始文本稳。对应我们状态机 `extracted → split` 之间细分（实现层，不改动状态机语义）。

### 2.4 拆卷报告 = 校验报告范式 ★印证

MathBank 每次拆解出分类计数报告，与我们的三层校验 + 行级错误定位同构。补一条：**拆题步也输出分类报告**（结构化成功 N 题 / 疑似小问合并 M 题 / 含图需核对 K 题 / 失败 J 题），教师确认前先看总量对不对——低成本建立信任。

### 2.5 智卷工坊的"生成前分析确认" ★理念一致，无新增

它的两阶段生成（分析→确认→生成）与我们的"草稿→确认队列"同构，验证了方向；试卷导入侧无直接可抄内容。

## 3. 明确不吸收的点

| 项 | 理由 |
| --- | --- |
| TikZ 几何重绘闭环自愈 | 依赖本地 XeLaTeX 编译回路，服务端部署成本高；几何图重排 P1-P3 都不是刚需（题干带原图即可），列为观察项 |
| 并发解题管道 | 它的产品是"解题"，我们 P1 是"得分录入"，作答回流在 P3 |
| 拆题后直接自动打标（无确认流） | 它没有知识图谱约束和教师确认环节；我们的置信度分流 + 图谱候选约束是画像质量的底线，**不可省** |
| AGPL 代码 | 见 §5 |
