## 一、MathBank（JudgePeach/math-question-bank）

### 1.1 定位与形态

本地化**高中数学题库管理与组卷排版工作台**，单机运行（FastAPI + SQLite + Tailwind/KaTeX 前端），面向教师个人/教研室的桌面场景。**AGPLv3 协议**。

### 1.2 功能全景

| 能力域 | 具体内容 |
| --- | --- |
| 题库 | LaTeX 源码为正文一等公民；`\fillin`/`\paren` 宏规范化；四套教材大纲（人教 A/B、苏教、沪教）打标；CLI 检索（关键词/题型/难度/关联题目） |
| 试卷拆解 | **PDF 双策略分流**：Inspector 属性探测 → 页级置信度路由 → 原生矢量直提（毫秒级、0 视觉 token）优先，低置信/丢公式自动降级 VLM OCR，手动全图 OCR 兜底；**Word**：OMML + MathType OLE（MTEF v5）双通道解析，低置信公式保留原图人工核对；拆卷报告分类计数 |
| 组卷排版 | 1:1 A4 仿真：密封线、大标题、注意事项框、拖拽排序、留白高度调整、A3 答题卡、高考 19 题预设；本地 XeLaTeX 编译导出高考级 PDF（LRU 去重缓存） |
| AI 组卷 | 考点细目表 + 难度阶梯选题 |
| AI 工程 | Harness 工作流：置信度路由（省 token）、几何重构闭环自愈（VLM 识图→TikZ→XeLaTeX 编译→失败日志回喂→自动纠错循环）、试卷切片并发解题管道；prompts 集中管理、结构化 JSON 容错解析、有界异步任务管理（取消/资源生命周期） |
| 大纲体系 | 四套大纲为版本化 JSON 资源；**切换教材自动智能映射，题目无需重标** |
| 数据工程 | 版本化迁移（升级前自动备份）；完整备份含逐文件 SHA-256 清单；恢复校验 + 停机锁；AI 只读题库（导出给 LLM 时**过滤答案**防泄露） |

### 1.3 强项与边界

- **最强资产**：PDF/Word 试卷拆解的工程深度（双策略分流 + 置信度路由 + 兜底通道），README 明示这是其性能与成本优势所在（原生提取不花视觉 token）。
- **明显边界**：单机单用户、无学生作答回流、无掌握度/画像、大纲只有目录树**没有前置依赖 DAG**、无多租户——它是"卷的生产端"，不涉及"卷的消费端"。

## 二、智卷工坊（DreZeo/examcraft-ai）

### 2.1 定位与形态

**AI 出卷桌面应用**（Tauri 2 + Rust + React 19 + TS + Vite + Tailwind v4 + Zustand + Zod + i18next），从需求描述直接生成整卷并排版打印。**MIT 协议**。

### 2.2 功能全景

| 能力域 | 具体内容 |
| --- | --- |
| 受控生成 | **两阶段**：Phase 1 分析需求→用户确认→Phase 2 结构化生成；与"AI 只产草稿"原则同构 |
| 校验链 | JSON 提取（容忍 Markdown 代码块包裹）→ Zod schema 校验 → 题型策略校验 → 失败**自动回喂自我修正** |
| 题目模型 | 题型：单选/多选/判断/填空/简答/论述/计算；字段：分值/参考答案/**评分点**/解析/代码/公式；内容为 Markdown+GFM+KaTeX |
| 排版 | Word 级：纸张（A3/A4/A5/B5 等）/横竖向/页边距/中文字号（小五~四号）/行距/页眉页脚/页码格式；**实时分页预览（预览分页=打印分页）**；**教师版/学生版双视图** |
| 导出 | JSON / Markdown / 打印 PDF（复用分页布局） |
| AI 配置 | OpenAI 兼容任意端点（含 Ollama 本地）；per-model temperature/max tokens；AI 智能体角色（学科/出题风格）；联网搜索联动（Tavily/Exa/Firecrawl，模型按需在同一轮发起搜索） |
| 数据 | 本地优先存储；数据目录**安全迁移**（先复制后切换，旧目录保留）；API Key 存系统钥匙串 |

### 2.3 强项与边界

- **最强资产**：受控生成的工程范式（两阶段 + 分层校验 + 自我修正）与排版体验（双视图、分页保真）。
- **明显边界**：无题库选题（LLM 自由生成为主）、无导入解析、无学生数据——同样是"卷的生产端"，且走的是 AI 生成路线而非题库路线（与我们"题库优先、变式受控"的决策相反，其经验主要取校验与排版部分）。

## 三、对比与定位差异

| 维度 | MathBank | 智卷工坊 | 本平台 |
| --- | --- | --- | --- |
| 形态 | 单机 Web 工作台 | 单机桌面应用 | **多租户 SaaS / 校内私有化服务** |
| 试卷来源 | 导入真实试卷（拆解） | AI 生成 | 题库 + 导入拆解 +（P3）受控变式 |
| 知识体系 | 四教材大纲（目录树） | 无 | 三级体系 + 前置 DAG + 可测量能力点 |
| 学生侧 | **无** | **无** | 作答回流 → 掌握度 → 画像 → 个性化练习 → 再评估（核心闭环） |
| 数据资产 | 题库 | 试卷文档 | 题库 + **学习轨迹事件流 + 干预效果**（长期壁垒） |

> 核心判断：两者与我们的重叠面仅在「题库 → 卷」这一段生产端；「卷 → 作答 → 画像 → 干预」的消费端是空白，恰是我们的产品价值所在。因此吸收策略是**支撑域取经、核心域自建**。

## 五、全局吸收策略：三项高优先修订

1. **05 试卷接入——解析分流升级**（最高优先）
   原设计「文字版直提 / 扫描件直接失败」两级 → 升级为三级：L1 原生矢量直提（0 token）→ L2 页级置信度路由、低置信页单独 VLM → L3 全图 OCR（教师确认后）。L2/L3 从 P2 提前至 **P1.5**，作为答题卡采集（06 的生死线）的前置能力。

2. **09 练习生成——教师批改版练习卷**
   同一份数据出学生版（作答留白）与教师批改版（答案 + 评分点 + 预期薄弱生）。把 Rubhop 评分点从系统内暗知识变成纸面可见——教师按得分点给分，回流数据才能支撑 Error Pattern 维度激活（08 的 P2 条件）。**打印卷反哺数据质量**的关键一招，成本低价值高。

3. **12 LLM 能力层——能力位矩阵 + 四层校验链**
   配置从单一 Provider 改为 `{text, vision}` 能力位（各配各的模型，服务私有化分流）；校验链定为：容错 JSON 提取 → pydantic schema → 领域策略 → **结构化错误清单回喂自修正**（≤2 次）。辅以任务三纪律：有界并发、可取消、诊断结构化（input_sha）。

其余修订项见各模块参考吸收建议的 backlog 节（共 20+ 条，均已映射到设计文档具体章节）。

## 六、协议与合规红线

| 项目 | 协议 | 红线 |
| --- | --- | --- |
| MathBank | **AGPLv3** | 设计思想、规格、架构思路可借鉴；**代码零复制**。AGPL 对网络分发（SaaS）有强传染义务，任何代码进入我们的仓库都会触发开源合规风险。其大纲内容数据如需复用，需另行确认授权——稳妥做法是用自己的冷启动流水线生成图谱，仅对照其粒度校准 |
| 智卷工坊 | MIT | 可参考实现细节；直接借用代码片段时保留其版权与许可声明 |

补充纪律（已写入 12-ai 参考建议）：不采纳 MathBank README 中第三方中转站的用法——面向学校的 SaaS 只支持官方 API 与自部署端点。
