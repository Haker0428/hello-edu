## 一、文档说明

### 1.1 设计目标

把需求文档中的闭环落地为一套可实施的模块化架构：

```
课程 → 知识点 → 题目 → 学生作答 → 错因/得分点 → 掌握度 → 学生画像 → 个性化练习 → 再评估
```

架构上对应的本质是：**以 `StudentAnswer` 为核心事件的事件驱动系统**——所有作答进入一条 append-only 事件流，掌握度引擎消费事件维护 `Mastery + Confidence` 状态，画像与练习生成读取状态产出动作。

### 1.2 三条全局设计原则

| # | 原则 | 架构含义 |
| --- | --- | --- |
| P1 | **可解释优先于精准** | 每个画像数字必须能下钻到证据（具体哪几题、哪个得分点）；算法用白盒纯函数，不用黑盒模型 |
| P2 | **教师时间是最稀缺资源** | 每个交互路径按"秒级确认、异常才处理"设计；所有批量动作有默认值 |
| P3 | **算法可替换、数据可回放** | 掌握度引擎是纯函数 + 事件溯源，换算法 = 重放历史事件，不丢数据 |

### 1.3 与需求文档的差异决策

以下为设计层面对需求的修正（已在评审沟通）：

| 需求原文 | 本设计决策 | 理由 |
| --- | --- | --- |
| 答题卡识别列为 Level 2（后期） | **提前至 Phase 2 前置项** | 逐题得分采集是全闭环摩擦最大环节，是生死线 |
| 画像含 Knowledge / Skill / Error Pattern 三维度 | MVP 中 **Skill、Error Pattern 明确降级**：只有逐题对错时无法区分错误模式 | 技术诚实，避免过度承诺；见 [4.7 画像模块](#47-profile-画像模块) |
| AI 自动标知识点 + 教师确认 | 增加**置信度分流**：高置信自动通过，低置信才进确认队列 | 否则确认环节成为新的教师负担 |
| 未提合规 | 增加**未成年人数据合规**与**校内网私有部署**选项 | 学校采购硬约束 |

### 2.1 系统上下文（C4-L1）

```
                 ┌─────────────┐        ┌─────────────┐
                 │  学科教师    │        │   班主任     │
                 └──────┬──────┘        └──────┬──────┘
                        │ 上传试卷/导入成绩/确认标注   │ 跨学科视图
                        ▼                        ▼
 ┌─────────────┐   ┌──────────────────────────────────┐   ┌────────────┐
```

### 2.3 核心架构决策（ADR 摘要）

| # | 决策 | 选择 | 备选与放弃理由 |
| --- | --- | --- | --- |
| ADR-1 | 服务形态 | **模块化单体** + 按限界上下文分包 | 微服务：团队小、域间调用频繁，分布式复杂度不值得 |
| ADR-2 | 事实存储 | **事件溯源（轻量版）**：`student_answer_event` append-only，`mastery_state` 为可重算的物化快照 | 只存状态：画像不可解释、算法升级后无法回放重算历史 |
| ADR-3 | 知识图谱存储 | PostgreSQL 邻接表 + 递归 CTE | Neo4j/图库：一学期 ~150 节点 + 数百边，PG 绰绰有余，运维省一件 |
| ADR-4 | 掌握度算法 | V1 指数移动更新（纯函数），策略接口预留 BKT/IRT | 直接上 BKT/DKT：不可解释、无冷启动数据校准参数 |
| ADR-5 | 多租户 | School 为租户边界，**PostgreSQL RLS**（行级安全）+ 应用层双保险 | 应用层过滤：容易漏；schema-per-tenant：迁移运维重 |
| ADR-6 | LLM 接入 | **Provider 抽象层**，云端 API 与私有化模型可切换，结构化输出（JSON Schema 约束） | 绑死云 API：违反"数据不出校"的私有部署需求 |
| ADR-7 | 技术栈 | Django + DRF + Celery；前端 React + Vite + ECharts | NestJS/Spring Boot 亦可；选 Python 因 PDF/Excel/LLM 生态最顺，且团队熟悉度优先 |
| ADR-8 | 异步机制 | Celery + Redis（进程内事件总线起步，天然演进为消息驱动） | 引入 Kafka/RabbitMQ：MVP 事件量（万级/校/学期）远不需要 |
| ADR-9 | Agent 运行时 | **提案 v0.2**：12-ai 模块拆为独立 FastAPI 服务（agent 网关），承载 agent 循环 / SSE 流式 / 两阶段确认会话 / 实时事件推送；写库仍只经 Django（RLS+审计） | 留在 Django 内：SSE 体验差、长连接与短请求伸缩 profile 不同 |
| ADR-10 | 前端栈 | React + Vite + TS + Zustand（编辑器/会话状态）+ TanStack Query（服务端状态，事件驱动失效）；AntD 暗色 token 落 HUD 主题，热力图/编辑器/聊天/证据链四个面自研 | Next 全栈或 NestJS BFF：双后端语言复杂化鉴权与 RLS |
| ADR-11 | Agent 编排 | 自研薄状态机 + provider 原生 tool-calling（操作白名单）+ pydantic 四层校验；批量走 Celery、流式走 agent 网关 | LangGraph/LangChain：窄域工作流+教师确认场景，确定性优先于自主性 |
| ADR-12 | Agent 框架评估 | **评估过 Claude Agent SDK（Claude Code API）与 pi-agent：均不作为产品核心**。前者限 Claude 模型（违反 ADR-6 私有化可切换）、成本与任务形态不匹配，仅用于内部离线工具（图谱冷启动）与开发流程；后者理念与 ADR-11 一致，仅作设计参考不引依赖（单人维护/TS 栈/许可待核验） | P3 AI Tutor 若需框架级自主性，届时再评估且必须 provider-agnostic |

### 2.4 技术选型清单

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 前端 | React 18 + Vite + TypeScript + Ant Design + ECharts | 热力图/趋势图用 ECharts |

## 三、领域模型与数据设计

### 3.1 领域划分（DDD 限界上下文）

| 类别 | 上下文 | 模块 | 一句话职责 |
| --- | --- | --- | --- |
| **核心域** | 掌握度 | `mastery` | 事件 → Mastery/Confidence 状态 |
| **核心域** | 画像 | `profile` | 状态 → 三维度学生画像 |
| **核心域** | 练习 | `practice` | 画像 + 教师策略 → 练习计划与成卷 |
| **核心域** | 教学看板 | `dashboard` | 状态 → 异常识别与行动入口 |
| 支撑域 | 知识图谱 | `knowledge` | 三级知识体系 + 前置 DAG |
| 支撑域 | 题库 | `question` | 题目、知识点映射、难度画像、Rubric |
| 支撑域 | 数据接入 | `ingestion` | 试卷拆题 + 成绩导入（全系统数据入口） |
| 支撑域 | AI 能力 | `ai` | LLM 调用的统一封装与校验 |
| 通用域 | 组织与租户 | `platform` | 学校/班级/学生/教材、多租户 |
| 通用域 | 认证授权 | `auth` | 账号、RBAC 三角色 |
| 通用域 | 文件导出 | `file` | 上传存储、练习卷打印导出 |

### 3.2 核心实体关系（ER 概览）

```
School 1─* ClassRoom 1─* Student
School 1─* Curriculum 1─* KnowledgePoint (自关联树: chapter→kp→ability)
KnowledgePoint ──kp_edge(prerequisite)──▶ KnowledgePoint      [DAG，防环]
Question *─* KnowledgePoint   (question_kp_map: weight + confidence)
Question 1─* ScoringRubric    (步骤/得分点)
Paper 1─* PaperQuestion *─1 Question
Exam(Paper, Class) ── 成绩导入 ──▶ StudentAnswerEvent ──▶ MasteryState
MasteryState ──▶ StudentProfile
Student 1─* Intervention  (P2)
PracticePlan ──▶ ExerciseSet ──▶ 导出 PDF/Word
```

### 3.3 核心表结构（关键 DDL 摘要）

```sql
-- ========= 事件表：全系统唯一事实源，append-only =========
CREATE TABLE student_answer_event (
    id            BIGSERIAL PRIMARY KEY,
    school_id     BIGINT NOT NULL REFERENCES school,      -- RLS 键
    student_id    BIGINT NOT NULL REFERENCES student,
    question_id   BIGINT NOT NULL REFERENCES question(id), -- 锚定题目版本
    exam_id       BIGINT REFERENCES exam,
    is_correct    BOOLEAN,
    score         NUMERIC(5,1),                            -- 逐题得分（含步骤分）
    max_score     NUMERIC(5,1) NOT NULL,
    evidence      JSONB NOT NULL DEFAULT '{}',
    --   evidence 结构:
    --   { time_spent_s, used_hint, independent, source_type,
    --     error_tags[], rubric_scores{step_no: score},
    --     question_map_confidence, difficulty_at_answer }
    source        VARCHAR(16) NOT NULL,   -- excel | answer_card | photo | manual | app(P3)
    occurred_at   TIMESTAMPTZ NOT NULL,   -- 作答发生时间（考试日期）
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    batch_id      UUID                    -- 同一次导入的批次（可撤销的追溯单元）
);
CREATE INDEX idx_sae_student ON student_answer_event(student_id, occurred_at);
-- 禁止 UPDATE/DELETE：应用层纪律 + 触发器拦截；撤销导入走补偿事件

-- ========= 物化状态：可由事件全量重算 =========
CREATE TABLE mastery_state (
    student_id       BIGINT NOT NULL REFERENCES student,
    kp_id            BIGINT NOT NULL REFERENCES knowledge_point,
    mastery          NUMERIC(5,2) NOT NULL,   -- 0~100
    confidence       NUMERIC(5,2) NOT NULL,   -- 0~100
    evidence_count   INT NOT NULL DEFAULT 0,
    last_evidence_at TIMESTAMPTZ,
    last_verified_at TIMESTAMPTZ,             -- 最近一次"验证型"作答
    readable_status  VARCHAR(16),             -- 教师可读档位（缓存，映射计算）
    strategy_version VARCHAR(16) NOT NULL,    -- 记录由哪个算法版本产出
    updated_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (student_id, kp_id)
);

-- ========= 知识图谱 =========
CREATE TABLE knowledge_point (
    id            BIGSERIAL PRIMARY KEY,
    curriculum_id BIGINT NOT NULL REFERENCES curriculum,
    scope         VARCHAR(8) NOT NULL,   -- platform | school | teacher
    owner_id      BIGINT,                -- school/teacher 层的归属者
    semantic_code VARCHAR(64) NOT NULL,  -- 稳定语义 ID（教师改显示名不改它）
    display_name  VARCHAR(128) NOT NULL,
    layer         VARCHAR(8) NOT NULL,   -- chapter | topic | kp | ability
    parent_id     BIGINT REFERENCES knowledge_point,
    status        VARCHAR(8) NOT NULL DEFAULT 'active',
    meta          JSONB DEFAULT '{}'     -- 学习目标、常见错误类型等
);
CREATE TABLE kp_edge (                       -- 前置关系 DAG
    prerequisite_id BIGINT NOT NULL REFERENCES knowledge_point,
    successor_id    BIGINT NOT NULL REFERENCES knowledge_point,
    PRIMARY KEY (prerequisite_id, successor_id)
);  -- 写入前做拓扑校验（见 4.2）

-- ========= 题目 =========
CREATE TABLE question (
    id                 BIGSERIAL PRIMARY KEY,
    school_id          BIGINT NOT NULL,          -- 平台标准题为 0（全局共享）
    type               VARCHAR(16) NOT NULL,     -- choice | fill | solve ...
    stem               TEXT NOT NULL,
    answer             TEXT,
    source             VARCHAR(16) NOT NULL,     -- bank | exam_import | ai_variant
    parent_question_id BIGINT,                   -- ai_variant 的母题
    difficulty_profile JSONB NOT NULL,           -- 五维难度画像
    --   { knowledge_level, computation, reasoning, reading_comp, kp_count } 各 1~5
    version            INT NOT NULL DEFAULT 1,
    status             VARCHAR(12) NOT NULL      -- draft | active | retired
);
CREATE TABLE question_kp_map (
    question_id BIGINT NOT NULL REFERENCES question,
    kp_id       BIGINT NOT NULL REFERENCES knowledge_point,
    weight      NUMERIC(4,3) NOT NULL,           -- 同题归一化权重
    confidence  NUMERIC(3,2) NOT NULL,           -- 标注来源置信度
    source      VARCHAR(8) NOT NULL              -- platform | ai | teacher
);
```

> 完整 DDL（含 `exam`、`paper`、`intervention`、`practice_plan` 等约 25 张表）在实施时以迁移脚本为准，此处只列决定架构形态的四张。

### 3.4 事件流与数据流向

```
                    ┌──────────── 数据入口（支撑域）─────────────┐
                    │  Excel 成绩导入   试卷拆题   答题卡(P2)      │
                    └──────────────────┬────────────────────────┘
                                       ▼ 校验/去重/批次化
                       ◆ student_answer_event（append-only）
                                       │
                     Celery worker 异步消费（幂等，按 batch 幂等键）
                                       ▼
                       ◆ mastery_state（按 question_kp_map.weight
                           将证据分摊到各知识点后更新）
                                       ▼
                       ◆ student_profile  ──▶  dashboard 异常识别
                                       ▼
                       practice（读取画像+教师策略 → 练习卷）
                                       ▼
                       学生作答（P1 为纸质/课堂，P3 回流 app）
                                       └──▶ 新事件，闭环
```

### 3.5 多租户策略

- `school_id` 为租户键，所有业务表携带；**PostgreSQL RLS 强制** + Django 中间件自动注入查询条件（双保险）。
- 平台标准知识图谱、标准题库为**共享只读数据**（`school_id = 0`），校级/教师级覆写落在自己租户内。
- 私有化部署形态（单校单机）与 SaaS 形态**同一套代码**，仅部署编排不同。

## 四、模块详细设计

> 每个模块统一按：**职责 / 对外接口 / 数据 / 核心逻辑 / 依赖 / Phase** 描述。

### 4.1 platform — 基础数据与租户（通用域）

| 项 | 内容 |
| --- | --- |
| 职责 | 学校、班级、学生、学期、教材选择、多租户隔离 |
| 对外接口 | `POST /schools`、`POST /classes`、`POST /classes/{id}/students:import`（名单 Excel）、`PUT /classes/{id}/curriculum`（绑定教材） |
| 数据 | `school` `school_user` `class_room` `student` `curriculum` `textbook` |
| 核心逻辑 | 学生名单 Excel 导入（学号模糊匹配去重）；班级绑定 curriculum 后**自动展开**标准知识点树为该校可用视图 |
| 依赖 | auth（角色）；knowledge（绑定教材时联动） |
| Phase | P1；RLS 第一天启用 |

### 4.2 knowledge — 知识图谱模块（支撑域）

| 项 | 内容 |
| --- | --- |
| 职责 | 三级知识体系（平台/学校/教师）、四层结构（课程→章节→知识点→可测量能力点）、前置关系 DAG、语义 ID 稳定性 |
| 对外接口 | `GET /curriculums/{id}/knowledge-tree`（按班级展开教师覆写后的视图）、`POST /kps`（教师自定义）、`PATCH /kps/{id}`（仅显示名/开关）、`POST /kp-edges`、`GET /kps/{id}/prerequisite-chain`（递归 CTE） |
| 数据 | `knowledge_point` `kp_edge` `learning_objective` |
| 核心逻辑 | ① **DAG 防环**：加边前对受影响子图做拓扑排序校验，成环即拒绝；② **三级覆写**：教师层只允许 `display_name`/`enabled`/新增自定义点，`semantic_code` 不可改——同一知识不产生多个 ID；③ 前置链追溯：`WITH RECURSIVE` 查询某知识点的前置断点（供 mastery 归因和练习引擎用） |
| 依赖 | platform |
| Phase | P1 只读平台标准层 + 教师显示名覆写；P2 开放校级教研组编辑 |

### 4.4 ingestion（一）— 试卷接入流水线（支撑域）

**输入**：试卷 PDF / Word / 拍照。**输出**：已确认标注的题目集合 + 一场考试的试卷结构。

流水线为**状态机 + 异步任务**，每步产物落库、可断点续跑：

```
uploaded ──▶ extracted ──▶ split ──▶ annotated ──▶ confirmed(教师)
   │            │            │           │
 文件落地     PyMuPDF      LLM 拆题    LLM 标注
             文本/图像     (结构化输出)  (图谱约束)
```

| 步骤 | 实现 | 质量控制 |
| --- | --- | --- |
| 抽取 | PyMuPDF 取文本 + 版面坐标；扫描件走 OCR（P1 支持文字版 PDF，扫描件提示转 Word） | 文本完整率检查 |
| 拆题 | LLM 结构化输出：题干/题型/分值/选项/答案，JSON Schema 约束 | 题号连续性 + 分值总和 = 卷面总分校验，不过自动重试 |
| 标注 | LLM 在**图谱候选集内**选题知识点 + weight（不允许标出图谱外的新点） | 每条映射带 confidence |
| 确认 | 教师确认队列 UI：**高置信（≥0.9）默认折叠直接通过，低置信高亮逐条确认**（P2 原则） | 教师修正回流为标注评测集 |

### 4.5 ingestion（二）— 成绩导入模块（支撑域）

**全系统最重要的数据入口。** 输入：按模板填写的 Excel（学生 × 逐题得分矩阵，模板随试卷确认自动生成——行列即题目列表）。

```
上传 Excel ──▶ 解析 ──▶ 三层校验 ──▶ 预览确认 ──▶ commit
                          │
                ① 名单校验：学号/姓名匹配班级学生（模糊匹配给建议）
                ② 范围校验：0 ≤ 得分 ≤ 该题满分
                ③ 完整性：缺学生/缺题/重复行，行级错误报告定位到单元格
```

- **commit 时**批量写入 `student_answer_event`（带同一 `batch_id`），**幂等**：同 batch 重放不产生重复事件。
- **撤销**：不做物理删除，录入负向补偿事件（`meta.revoke_of` 指向原 batch），重放自然抵消——保住 append-only 语义。
- 得分率换算：`is_correct = (score == max_score)`；部分得分进 `evidence.rubric_scores`（若教师按得分点录入）。

| 对外接口 | `GET /exams/{id}/score-template`（下载模板）、`POST /exams/{id}/scores:import`（校验+预览）、`POST /exams/{id}/scores:commit`、`POST /batches/{id}:revoke` |
| --- | --- |

| 依赖 | exam/paper 结构、student 名单 |
| Phase | P1（Excel）；P2 增加答题卡识别与"改卷点击录入"两种 source，事件结构不变 |

### 4.6 mastery — 掌握度引擎（核心域）

**纯函数 + 事件驱动**。这是全系统算法核心，也是可解释性的来源。

```python
# 策略接口（可替换）：换算法 = 新策略类 + 重放事件
class MasteryStrategy(Protocol):
    version: str
    def apply(self, state: MasteryState, ev: Evidence) -> MasteryState: ...

class ExponentialV1(MasteryStrategy):
    """M_{t+1} = (1-α)·M_t + α·E_t，α 由置信度/数据量/难度动态决定"""

    def apply(self, s, ev):
        # 1) 证据评分 E ∈ [0,100]：得分率为主，非独立完成/使用提示折扣
        E = ev.score_rate * 100
        E *= 0.7 if not ev.independent else 1.0
        E *= 0.85 if ev.used_hint else 1.0
        E *= ev.question_map_confidence          # 题目标注置信度折扣

        # 2) 学习率 α：数据少→新证据权重大；数据多→偶然失误不致剧烈波动
        α = self.base_alpha
        α *= 1.0 + 0.5 * ev.difficulty_gain      # 做对难题，证据更强
        α *= max(0.3, 1.0 - s.confidence / 100 * 0.6)
        α = clamp(α, 0.05, 0.6)

        # 3) 更新
        M_new = (1 - α) * s.mastery + α * E
        C_new = min(100, s.confidence + self.evidence_gain(ev, s))
        return MasteryState(mastery=M_new, confidence=C_new,
                            evidence_count=s.evidence_count + 1, ...)
```

**一题多知识点的证据分摊**：设题目映射 {去括号 0.3, 移项 0.3, …}，则对每个 kp 分别 `apply(state_kp, ev × weight_kp)`——薄弱知识点不会因一道综合题被过度冲淡。

**时间衰减（每日 Celery 任务）**：

```
只降 Confidence，不动 Mastery：
C ← C × 0.5 ^ (距上次验证天数 / 半衰期90天)
若 C < 复习阈值(55) 且 M ≥ 熟练线 → 生成"复习检测"建议（进 practice 的复习桶）
```

**教师可读档位映射**（阈值租户级可配）：

| 档位 | 条件 |
| --- | --- |
| 未学习 | evidence_count = 0 |
| 未掌握 | M < 40 |
| 学习中 | 40 ≤ M < 60 |
| 初步掌握 | 60 ≤ M < 75 |
| 熟练 | 75 ≤ M < 90 |
| 稳定掌握 | M ≥ 90 |

**可解释性 API（P1 原则的落点）**：`GET /students/{id}/mastery/{kpId}/explain` → 返回最近 N 条参与计算的事件（题目、得分、当时的 E 和 α）——回答教师"凭什么说这学生 42%"。

| 项 | 内容 |
| --- | --- |
| 触发 | Celery 消费 `student_answer_event` 新增（按 batch 幂等）；每日衰减 job；算法升级触发全量重放 job（分学生分片，单学生事件量 ~数千条，秒级） |
| 依赖 | 事件表（只读）、question_kp_map（分摊权重）、knowledge（前置链） |
| Phase | P1 = ExponentialV1；P3 = BKT/IRT 策略并行灰度（按校切换 strategy_version 对比） |

### 4.7 profile — 画像模块（核心域）

消费 `mastery_state`，产出三维度画像。**按数据可得性诚实分级：**

| 维度 | P1（仅逐题对错/得分） | P2+（有 Rubric 得分点/作答时间） |
| --- | --- | --- |
| **Knowledge** | 完整支持：按章节/知识点聚合 M+C，含前置断点标注 | 同左 + 步骤级定位 |
| **Skill**（计算/建模/阅读提取/逻辑推理） | **降级**：通过 kp→skill 标签的静态映射间接估计，结果标注低置信（`estimate_only: true`），UI 明示"推测" | 有作答时间与难度画像后，逐题特征回归校准 |
| **Error Pattern**（符号错误/漏条件/粗心/跳步） | **不可用**：对错数据无法区分错误类型，UI 不展示该维度 | Rubric 逐得分点数据接入后激活：错在哪个步骤 → 映射错误模式 |

- 知识点与错误模式是**两套独立体系**（`error_type` 表独立于 `knowledge_point`），Rubric 行携带 `error_hint` 由 LLM 辅助归类、教师确认。
- 画像为**读时聚合 + 缓存**（Redis，事件后失效），不做宽表——维度会持续演进。
- 输出 API：`GET /students/{id}/profile`、`GET /classes/{id}/kp-summary`。

| 依赖 | mastery、question（Rubric）、knowledge |
| Phase | P1 Knowledge；P2 Error Pattern + Skill 校准 |

### 4.8 practice — 练习生成模块（核心域）

两层结构，对应需求 8：

```
PracticePlanner（练什么）            QuestionSelector（用哪些题）
输入: 学生画像 + 教学进度              输入: 练习计划 + 题库约束
     + 教师策略模板                    约束: 难度带 / 去重 / 间隔重复
输出: 知识点配比与题量分配             输出: 具体题目清单
```

**Planner 默认配比**（教师策略模板可调，P2 原则）：

```
50% 薄弱知识（当前教学范围内的低 M 知识点）
20% 前置知识（前置链断点处的诊断题）
20% 当前教学内容（跟随教学进度）
10% 历史复习（低 Confidence 触发的复习检测）
```

**Selector 选题约束**：

- **难度带**：目标成功率 ~70%——按学生当前 M 选题（M 低→基础题，M 高→进阶题），实现"自适应难度"而非固定星级；
- **去重**：排除该生 `question_exposure_log` 中近 N 天曝光题；优先复现"做错且未重测"的题；
- **间隔重复**：复习桶按简单间隔表（1d/3d/7d/14d）排序；
- 题量不足时降级提示教师（不擅自 AI 出题——P1 无变式生成）。

**成卷输出**：`Homework = Common + Personalized`，统一题 60% + 个性化 40% 分区排版；**WeasyPrint 模板化导出 PDF**（A4 双栏、答题区域留白、生名单独成卷带姓名页眉），也支持 Word。打印友好是一级需求，不是附属功能。

| 对外接口 | `POST /practice-plans`（班级/个人，含策略参数）、`GET /practice-plans/{id}`、`GET /practice-plans/{id}/export?format=pdf`、`POST /practice-plans/{id}:assign`（记录为作业，等待成绩回流） |
| --- | --- |
| 数据 | `practice_plan` `exercise_set` `exercise_item` `question_exposure_log` |
| 依赖 | profile、question、knowledge、file |
| Phase | P1 全量；P3 接 AI 变式生成扩充选池 |

### 4.9 dashboard — 看板与异常识别（核心域）

**Exception-based Management 的落点**：不展示"所有数据"，只回答教师首页三问——*今天班级有什么问题？哪些学生需要关注？下一步做什么？*

**异常识别规则引擎**（规则表驱动，可配置）：

| 规则类型 | 触发条件（示例，租户可调） | 产出动作入口 |
| --- | --- | --- |
| 学生-知识点 | 当前教学章节核心 kp `M < 40` | → 生成该生专项练习 |
| 学生-前置断点 | 当前章节弱 且 前置链某节点也弱 | → 生成前置诊断练习（而非刷高层题） |
| 学生-复习候选 | `M ≥ 75 但 C < 55`（可能遗忘） | → 安排复习检测题 |
| 知识点-班级 | 某 kp 全班均值 < 60 且分布集中 | → 提示**全班性教学问题**（非个别补差），建议课堂重讲 |
| 学生-整体 | 多 kp 连续下滑 / 班主任视角跨学科风险 | → 标记关注 + 通知班主任 |

**关键设计**：每个异常卡片直接挂**行动按钮**（发起练习 / 记录干预 / 查看证据链）——Action Dashboard，异常不是图表是待办。

**班级热力图**（ECharts）：学生 × 知识点矩阵，色阶 = M，点大小/描边 = C（低置信描边提示"数据不足"）；单元格点击下钻证据链。

| 对外接口 | `GET /classes/{id}/dashboard`（三问聚合）、`GET /classes/{id}/heatmap`、`GET /students/{id}/timeline` |
| --- | --- |
| 依赖 | mastery、profile、knowledge（当前教学进度） |
| Phase | P1 |

### 4.10 intervention — 干预闭环（核心域，P2）

```
问题(异常快照) → 教师干预(方式/内容) → 后续表现(追踪窗口内 M 变化) → 效果判定
```

- `intervention` 表记录：触发异常快照（JSONB，冻结当时状态）、干预类型（重讲/专项练习/个别辅导/家长沟通）、关联的 `practice_plan_id`、追踪窗口（默认 14 天）。
- 效果判定 job：窗口结束时对比目标 kp 的 M 变化（如 42% → 76% 记为有效），**注意归因诚实**——只记录相关性，措辞用"干预后变化"不用"干预导致"。
- 长期积累形成"什么类型学生 × 什么干预方式 → 什么效果"的策略推荐数据集（P3）。

### 4.11 ai — LLM 能力层（支撑域）

**所有 LLM 调用的唯一入口**，三个能力 + 两道防线：

| 能力 | 用途 | 结构化约束 |
| --- | --- | --- |
| 拆题 | 试卷 → 题目列表 | JSON Schema（题号/题干/题型/分值/答案），校验不过自动重试 ≤2 次 |
| 标注 | 题目 → 知识点映射 | **候选集约束**：只允许从当前图谱知识点中选，输出 weight + confidence |
| 变式（P3） | 母题 → 变式题 | 变换数字/语境，**知识点映射必须与母题一致** |

**两道防线**：
1. **Provider 抽象**：`LLMProvider` 接口 + 云端/私有化（vLLM 等）双实现，部署形态可切换——满足"数据不出校"；
2. **校验器（P3 变式题强制）**：答案一致性校验（数学题用符号计算/数值代入验算），不过校验的变式题**永不入库**。

**评测集与质量闭环**：拆题/标注的 LLM 输出与教师修正的差异持续沉淀为评测集，每次换模型/换 prompt 跑回归——这是"AI 能力"不退化的保障。

| 对外接口 | 模块内部服务（不暴露 HTTP），`split_paper()` `annotate_question()` `generate_variant()` |

| 依赖 | 无外部模块依赖（被 ingestion/question 依赖） |
| Phase | P1 拆题+标注；P3 变式 |

## 七、非功能设计

### 7.1 性能与容量边界

| 场景 | 量级 | 设计余量 |
| --- | --- | --- |
| 单班一次考试 | 50 人 × 30 题 = 1,500 事件 | Celery 单 worker 秒级消化 |
| 单校期中 | 40 班 ≈ 6 万事件 | 批量导入 + 分片消费，分钟级 |
| 单学生全量重放 | ~数千事件 | < 1s，算法升级重算可夜间分片跑 |
| 看板查询 | 热力图 50×100 单元格 | Redis 缓存 + 事件后定向失效 |

MVP 阶段 PG 单机 + 2 worker 足够；增长瓶颈最先出现在看板聚合，届时引入物化视图而非改架构。

### 7.2 安全与合规（未成年人数据，一级约束）

- **数据最小化**：V1 不收集学生手机号/身份证/家庭信息，仅姓名+学号；
- RLS 强制租户隔离 + 全量审计日志（谁在何时看了/改了什么）；
- 数据主体权利：学校可导出（JSON/PDF）与删除本校数据，删除走软删 + 事件匿名化（保留统计、抹去身份）；
- 私有化部署选项：docker-compose 单机进校内网，LLM 切私有化 Provider；
- 备份：每日全量 + WAL 归档；事件表是"不可再生资产"，异地备份优先级最高。

### 7.3 可观测性

- structlog 结构化日志，`request_id` / `batch_id` / `event_id` 全链路贯穿；
- 关键业务指标埋点：导入成功率、确认队列平均修正条数（**标注质量的直接信号**）、练习生成→成绩回流率（**闭环健康度的核心指标**）；
- Sentry 错误追踪（可自托管）。

## 八、演进路线与模块启停

| Phase | 目标 | 启用模块 | 明确不做 |
| --- | --- | --- | --- |
| **P0（2-4 周，无代码）** | 验证采集假设 | 无（Excel + 人工模拟全闭环） | — |
| **P1 MVP** | 跑通核心闭环 | platform / auth / knowledge(只读+覆写) / question / ingestion(Excel+PDF) / mastery(V1) / profile(Knowledge) / practice / dashboard / file | 手写 OCR、AI Tutor、家长端、学生端、变式生成 |
| **P2** | 降低采集摩擦 + 闭环加深 | + ingestion(答题卡/点击录入) / intervention / 教师策略模板 / 班主任跨学科视图 / profile(Error Pattern) | — |
| **P3** | 智能化 | + ai(变式生成+校验器) / mastery(BKT/IRT 灰度) / 学生端 App / AI Tutor | — |

**架构不变量**（任何 Phase 不得破坏）：
1. `student_answer_event` 永远 append-only；
2. `mastery_state` 永远可由事件 + 确定性策略全量重算；
3. 新数据源只允许新增 `source` 枚举值，不改事件结构；
4. LLM 永远不直接写状态，只产生**待确认草稿**（拆题/标注/变式一律如此）。

```
hello-education/
├─ apps/
│  ├─ web/                     # React 教师端（Vite + TS + AntD + ECharts）
│  └─ server/                  # Django 模块化单体
│     └─ apps/
```
